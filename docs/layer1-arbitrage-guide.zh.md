# 第一层:套利事件目录

> **[English →](layer1-arbitrage-guide.md)**

Kalshi 上所有"结算规则把价格绑定在一起"的市场族目录——交易所的可套利面,由对全部
~9,800 个开放 event 的扫描发现、经四轮审计验证。所有族及其成员事件在 `data/` 中
机器可读,并可用下方工具链随时重建。标注 2026-08-04 的数字会随挂牌漂移;方法不会。

## 1. 找到了什么

42 个发现的族加 9 个基础机制,经四轮审计和 16-agent 现实核查定级
(`data/discovered_families.csv`,`reaudit_verdict` + `reality_check` 两列):

| 等级 | 族 | 绑定性质 |
| --- | --- | --- |
| REAL-EXACT | 榜单名次恒等式(+ 事件内梯子等基础机制) | 双向锁 |
| REAL-ONE-DIRECTIONAL | ~13 个,含 获奖⇒提名、对阵拆分、让分⇒独赢、点值⊆梯子 | 单向锁 |
| CONDITIONAL | ~20 个,含整个同场体育格 | 指定条件消亡**之后**成锁(见 §3) |
| Salvaged-BROKEN | 8 个条件形式(球员首发、比赛举行……) | 同上处理 |
| NOT-REAL | 1 个(正副总统互斥)+ 10 个被拒的伪相似 | 非规则绑定——[陷阱清单](correlation-taxonomy.md) |

这些族在开放面上共生成 ~28,000 条独立的规则绑定价格约束——每一条都是机器可查的
不变量,任何定价模型、做市商或第二层账本都能拿来当免费的一致性校验。

## 2. 四条验证轴——信任任何配对之前全部跑完

每条轴的存在都是因为跳过它曾在本项目中造成真实的亏损型错误:

1. **规则文本,不是显示文本**——腿按 `rules_primary` 结算;副标题会骗人(显示的是
   人名,结算的是政党)。
2. **赔付分支一致性**——取消/FMP/作废条款必须匹配;带 FMP 分支的上半场腿对上二元
   全场腿,不需要任何逻辑违约就能击穿下限。
3. **结算源一致性**——两腿都 `GET /series`;ESPN 与 FIFA 的分歧让 0-0 ≡ ¬Over0.5
   都带基差风险。抽查过的每个体育联赛配对都不一致。
4. **可执行性**——两腿都双边报价且有过成交(`data/markets_index`);深度读
   `orderbook_fp`(`orderbook` 键永远为空);取两腿最小值。

## 3. 条件到期时钟——实用的边际

多数 CONDITIONAL 配对会在事件存续期内、其条件消亡时晋升为真锁:开球杀死取消分支,
首发名单公布杀死伤退分支,确认单场赛制杀死赛制分支。监控晋升时刻比为尾部定价便宜。

## 4. 工具链

```bash
python3 src/kalshi_structure/fetch.py       # 普查 → ~/Developer/kalshi-research-data
python3 scripts/run_scan.py                 # 全族扫描、逐系列费率、违约检测
python3 scripts/run_catalog.py              # 价格无关监控清单(relation_catalog.csv)
```

`Partition.evaluate_buy_all()` 在构造上拒绝非明示穷尽性和报价/腿不匹配——两者都是
审计发现,不要绕过。

## 5. 容量

这个面上的策略容量较小:绑定被钉得很紧、快端竞争充分,无法容纳大资金。适配的用法:
对族监控清单跑一个监控级账本(瞬时违约确实会出现——项目期间观察并验证过一个真实的
多腿篮子)、§3 的条件到期晋升,以及杠杆最高的用法——作为闸门校验库,守住第二层每一
笔相关性交易的风控。
